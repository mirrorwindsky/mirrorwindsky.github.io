## ——对攻击窗口、射击策略与可中断换弹的实现推测

《胜利女神：NIKKE》的基础战斗输入十分简单：玩家按住鼠标左键，角色从掩体中探出并瞄准；松开后结束本轮攻击并重新回到掩体。但在这组简单输入之下，不同武器、特殊技能和自动战斗却能表现出不同的射击规则，同时共享基本一致的掩体与换弹行为。

这里不讨论游戏实际源码，只从可观察行为出发，尝试推测一种能够解释这些现象的系统组织方式。

## “按住—松开”定义的可能不是开火，而是攻击窗口

对于步枪、冲锋枪、机枪和霰弹枪，玩家按住左键后角色持续保持瞄准，在准星覆盖有效目标时持续射击；松开左键后停止攻击并退回掩体。

普通狙击枪和发射器则不同：按下左键后开始蓄力，按住时间决定蓄力程度，但无需蓄满。只要玩家松开左键，当前蓄力的一发就会立即射出，随后角色同样回到掩体。

因此，“按住左键”似乎并不适合简单理解为“持续开火”。更统一的解释是：**按住代表维持一次攻击窗口，松开代表结束这次攻击窗口。至于攻击窗口内怎样产生射击，则由具体射击规则决定。**

角色层可以先抽象为：

```text
Cover / Idle
     │ 开始攻击
     ↓
Exposed / Attack
     │ 主动结束攻击 / 弹药耗尽
     ↓
Reloading
     │ 换弹完成
     ↓
Cover / Idle
```

而 `Attack` 内部再决定具体如何开火。

例如连续射击类武器可以近似表示为：

```text
Hold
 ↓
Aim
 ↓
Valid Target
 ↓
Repeat Fire
```

普通狙击枪与发射器则是：

```text
Press → Start Charge
Hold  → Increase Charge
Release → Fire(chargeAmount)
```

这样，同一套角色攻击状态就不必因为武器类型不同而整体重写。

## 特例：射击方式甚至不应与“武器类型”硬绑定

如果只观察普通角色，很容易进一步得到一个简单模型：

```text
步枪 / 机枪 → Continuous Fire
狙击枪 / 发射器 → Charge & Release Fire
```

但游戏中的特殊角色会打破这个对应关系。

例如狙击枪角色“小红帽”在特定技能开启后，虽然仍使用狙击枪，却会从通常的蓄力单发切换为按住连续射击。

部分特殊发射器又采用另一套规则：首先需要按住完成蓄力；蓄满以后，只要继续保持按键，就可以连续射击。一旦松开，再次攻击时则必须重新经历蓄力阶段。

也就是说，真正决定射击行为的可能并不是单纯的 `WeaponType`。

从实现角度看，更灵活的一种组织方式是让角色在当前状态下使用某一种 **Fire Policy（射击策略）**：

```text
Continuous Fire
Charge → Release Fire
Charge → Continuous Fire
...
```

普通狙击枪可能使用：

```text
ChargeReleaseFire
```

而“小红帽”开启技能时，可以动态切换为：

```text
ContinuousFire
```

特殊发射器则可以采用：

```text
Charging
   │ charge >= threshold
   ↓
ContinuousFire
   │ Release
   ↓
Reset
```

这样，**角色负责“是否处于攻击状态”，Fire Policy 负责“处于攻击状态时怎样打”**。角色、武器和技能只需要共同决定当前采用哪一种射击策略。

这种拆分也能够自然容纳未来更多特殊角色，而不必不断给角色主状态机增加例外判断。

## 回掩体后的自动换弹，是一个可被玩家打断的“默认行为”

换弹又体现了另一层公共规则。

实际操作中，如果角色保持满弹状态探出掩体但没有射击，松开左键后不会换弹；但只要消耗哪怕一发弹药，结束攻击后就会立即回到掩体并开始换弹。

因此，回到掩体以后很可能还存在类似：

```text
ammo < maxAmmo ?
```

的判断，而不是无条件进入 Reload。

更值得注意的是，Reload 并非必须完整执行到底。

如果弹匣中仍有剩余弹药，换弹过程中重新按住左键，会立即停止换弹并重新进入攻击；只有弹药已经完全耗尽时，玩家才无法打断换弹。

可以将这一行为概括为：

```text
结束攻击
    ↓
ammo < maxAmmo ?
    │
   Yes
    ↓
Reload
    │
    ├─ Attack Input && ammo > 0
    │          ↓
    │     Cancel Reload
    │          ↓
    │        Attack
    │
    └─ ammo == 0
               ↓
        Continue Reload
```

这使自动换弹同时承担了两种目的：

一方面，系统会主动利用玩家缩回掩体的空档，为下一轮攻击补充弹药，减少单独管理换弹的操作负担；

另一方面，只要仍有可用弹药，玩家就可以随时取消这项自动行为重新攻击，不会因为系统正在“帮忙换弹”而失去对攻击节奏的控制。

因此，自动换弹更像是**结束攻击窗口后的默认优化行为，而不是一个强制锁死玩家操作的流程。**

## 玩家与 AI 可能只负责决定“意图”

自动战斗下，角色也会自动瞄准和射击；弹药耗尽或场上没有合适目标时，则返回掩体，根据弹药状态进行换弹或待机。

这进一步提供了一种可能的系统划分：

```text
Player Input ─┐
              ├→ Attack Intent → Character State → Fire Policy
AI Decision ──┘
```

玩家和 AI 不必分别控制两套完整的角色行为。

它们只需要决定诸如“开始攻击”“继续攻击”“结束攻击”等意图；之后的探出掩体、换弹，以及当前武器具体怎样射击，都可以继续由公共系统处理。

## 从一个简单输入中拆出的三层职责

综合这些可观察行为，我认为一种能够较好解释 NIKKE 这套操作的实现思路，是把功能至少拆成三个层次：

**控制层**：玩家输入或 AI 决策，负责表达是否希望攻击。

**角色状态层**：负责 Cover、Attack、Reload 等公共状态，以及这些状态之间的转换条件。

**射击策略层**：负责攻击窗口内部具体如何产生射击，并允许受到角色、武器或技能影响而动态改变。

这样的组织方式能够解释几个看似矛盾的现象：普通狙击枪与步枪拥有完全不同的操作手感，却共享相似的掩体与换弹流程；同一个狙击枪角色又能够在技能期间临时变成连射模式；某些特殊发射器还能拥有“蓄满后持续射击”的第三种规则。

它们不一定需要分别维护一整套角色逻辑。真正变化的，可能只是攻击窗口内部的射击策略。

从一个玩家看来非常简单的“按住—松开”操作，背后因此可以同时兼容武器差异、技能特例、自动换弹以及手动 / 自动控制。而这套设计最值得注意的地方，也并不是状态数量有多复杂，而是**把稳定的公共行为与容易变化的射击规则拆开，让例外尽可能只影响它真正需要改变的那一层。**
